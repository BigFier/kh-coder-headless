# 示例：50 份员工离职访谈

这份语料是虚构的，50 个人讲自己为什么离职。用来试工具，不用装任何东西就能跑。

语料是 `corpus.txt`，一行一段，共 50 行，约 3,900 字。

## 先跑这个

```bash
khc words corpus.txt --at 3,4,5,8
```

输出：

```
  freq >=    3  ->  173 terms
  freq >=    4  ->  118 terms
  freq >=    5  ->   85 terms
  freq >=    8  ->   56 terms
```

这一步是定阈值。KH Coder 画共现网络时词太多会糊成一团，一般控制在 50 到 150 个词比较好看。看这张表，`--min 4` 大概是 50 多个词，合适。

## 然后画图

```bash
khc netgraph corpus.txt out/network.png --lang cn --min 4 --hinshi Noun,Verb --edges 50
```

出来的图（就是 `out/network.png`）大概能看出四块：

- **左上**：公司、人、问题、说、要、走、领导、流程、客户 —— 管理和公司的抱怨
- **右上**：工资、行业、来、给、加班 —— 钱的部分
- **左下**：技术、机会、个人、想、喜欢、看、下去 —— 职业发展
- **中间偏下**：项目、加班、让、上线、到、找、时候 —— 具体干活

`--hinshi Noun,Verb` 是只保留名词和动词。不写这个参数的话，图上会全是「不、就、也、都、很、但」这类虚词，把真正的内容挤掉。

## 词频表

```bash
khc freq corpus.txt out/freq.csv --lang cn
```

前几行长这样：

```
Noun,,Adj,,JJ,,Adv,,Verb,
公司,37,多,11,原来,2,不,42,做,33
人,24,高,9,同样,2,都,28,说,21
问题,24,好,5,大,2,就,26,要,18
技术,20,一样,3,实际,2,但,20,加班,10
领导,19,低,3,新,2,也,17,能,9
```

按词性分栏：名词、形容词、连词、副词、动词。左边是这个语料里最常出现的词。

最常说的是「公司」「人」「问题」「技术」「领导」。形容词里「多」出现 11 次，几乎是抱怨「太多」——加班多、会议多、出差多。

## 检索上下文

```bash
khc conc corpus.txt 加班 out/kwic.csv --lang cn
```

出来 18 条，每行一条命中，分成三栏：左文、关键词、右文。

第一条是：

> 在这家公司待了三年，最直接的感受就是 **加班** 太多了。不是偶尔加，是每天都要加到九点以后。

能直接看出「加班」在这个语料里是怎么用的——是抱怨的量，不是描述的制度。

## 换个词试

```bash
khc conc corpus.txt 工资 out/kwic2.csv --lang cn
khc conc corpus.txt 领导 out/kwic3.csv --lang cn
```

同一个语料，不同的词，出来的上下文完全不一样。这就是 KWIC 的用处：判断一个词的实际用法，而不是猜。

## 想自己试别的

改 `--min` 看词数怎么变，改 `--hinshi Noun` 只看名词，去掉 `--lang cn` 看自动识别行不行。

`out/` 里的三个文件是这么跑出来的，可以直接对着看。
